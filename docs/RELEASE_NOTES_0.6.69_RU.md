# LongMedia 0.6.69 — изменения относительно 0.6.63

Релиз объединяет локальные изменения 0.6.64–0.6.69 для пользователей публичной версии 0.6.63. Идентификаторы нод и форматы workflow сохранены. Для некоторых операций нужны совместимые сохранённые native TAKE: одного MP4 недостаточно для продолжения из кеша.

## Director и TAKE

- **Добавление после готовых клипов:** новому включённому GENERATED-клипу в конце больше не нужен старый TAKE. Отключённым GENERATED-клипам для воспроизведения по-прежнему нужны совместимые активные TAKE; границы перед замороженным соседом проверяются. При ошибке чтения или инициализации кеша запуск останавливается, а не превращается в полный рендер.
- **Перегенерация CUT-диапазона:** выберите интервал между CUT-маркерами, сохраните или перегенерируйте аудио и проверьте фактические границы на сетке H3 перед запуском. Источником служит активный TAKE клипа.
- **Двусторонний Bridge:** вставьте GENERATED-переход между совместимыми GENERATED-соседями и запустите его с закреплением обеих границ по активным TAKE. Результат остаётся ожидающим до просмотра и явного **ACCEPT** или **DISCARD**. При принятии повторно проверяются исходные ревизии, таймлайн, Global Prompt и обе AV-границы. Для неподходящей длительности меню предлагает доступные ближайшие значения сетки; при изменении сдвигаются последующие MAIN-клипы.
- **Отзывчивость TAKE:** файловые операции HTTP-обработчиков вынесены из event loop, чтение статуса не изменяет состояние, а большие тензоры подготавливаются до публикации под блокировкой проекта.
- Video-референс без звуковой дорожки больше не должен падать только потому, что загрузчик видео предоставляет ленивый аудиовыход.

Для Range и Bridge нужны MultiClip и совместимые исходные TAKE; Loop Closure должен быть выключен. В текущем native Bridge оба родителя должны быть GENERATED, а не MEDIA. Порядок действий и ограничения описаны в [руководстве по regeneration и TAKE](DIRECTOR_REGENERATION_GUIDE_RU.md).

## Runtime и совместимость

- Новая frames-aware H3 VideoVAE ComfyUI сохраняет собственную нарезку кадров, batching и склейку тайлов. Адаптер LongMedia для пакетирования тайлов остаётся для совместимых старых H3 VAE. Это исправляет несовпадение сигнатуры Decode из [#25](https://github.com/vizart-vj/ComfyUI-MiniMax-H3-LongMedia/issues/25) и [#26](https://github.com/vizart-vj/ComfyUI-MiniMax-H3-LongMedia/issues/26).
- Потоковый final output head H3 ограничен проходом LongMedia и восстанавливается после него, в том числе при исключении. Поддержаны актуальные раздельные PDD-сетки потоков. Это устраняет сохранение подменённого метода общей модели, описанное в [#16](https://github.com/vizart-vj/ComfyUI-MiniMax-H3-LongMedia/issues/16).
- В режиме Director `lip_sync` полная дорожка Audio 1 сохраняется вместе с тишиной в начале; guide audio для каждого клипа выбирается по глобальному времени ([#28](https://github.com/vizart-vj/ComfyUI-MiniMax-H3-LongMedia/issues/28)).
- Unified Sampler восстанавливает guider и hooks после ошибок и очищает model/control branches, полученные при подготовке. Ошибка очистки не подменяет исходную ошибку рендера. В логе отдельно отмечены подготовка, очистка, сохранение TAKE и Decode.
- При необходимости объединения MultiClip Decode собирает video latent views за одно выделение памяти и сохраняет native continuous VAE path.

Для новой frames-aware H3 VAE поле Decode `batch_size` не управляет batching тайлов. Поведение старой H3 VAE и других VAE описано в [параметрах Decode](PARAMETER_REFERENCE_RU.md#decode).

## Sampler и интерфейс

- `View` остаётся над входами и пресетами Sampler при пересоздании виджетов. Basic и Advanced скрывают пустые секции; workflow сохраняет порядок виджетов backend.
- Действия пресетов вынесены в отдельные кнопки **New preset**, **Overwrite preset** и **Delete preset**. Перезапись и удаление доступны после выбора пресета. Штатные элементы ComfyUI устраняют плавающую накладку из [#30](https://github.com/vizart-vj/ComfyUI-MiniMax-H3-LongMedia/issues/30).
- Перетаскивание Director обрабатывается по кадрам анимации; при общем масштабе используется облегчённая заглушка, а повторные обновления Director и Setup объединяются.

## Проверка и ограничения

Регрессионные тесты покрывают контракты новой и старой VAE, восстановление output head, PDD-сетки на тестовых тензорах, маршрутизацию Audio 1 с тишиной в начале, очистку Sampler и контракты Director Range/Bridge. Тесты интерфейса проверяют пресеты Sampler и взаимодействия Director. Эти проверки не заменяют исходные workflow и оборудование авторов issues.

В одной локальной сессии ComfyUI 0.46.0 на RTX 5080 последовательно завершились два обычных Director MultiClip-рендера. Само завершение не подтверждает визуальную непрерывность, качество lip sync и работу всех workflow. Для релиза отдельно не подтверждены полный GPU A/B обычного H3 до и после LongMedia для #16, сквозной lip-sync рендер с тишиной в начале для #28, прерывание генерации, а также все варианты Range/Bridge, low VRAM и multi-GPU.

Причина ситуации, когда Windows продолжает показывать PID после закрытия терминала ComfyUI, остаётся неподтверждённой. Очистка и диагностический лог изменены, но полное исправление исходной проблемы завершения процесса этим релизом не заявляется.

## Обновление

Сохраните резервную копию старой папки нод и пользовательских данных, остановите ComfyUI, замените папку `ComfyUI-MiniMax-H3-LongMedia` в `custom_nodes` папкой из релиза и перезапустите ComfyUI. Не держите две активные копии пакета. Сохраните ваши workflow, модели и библиотеку TAKE. См. [индекс документации](README_RU.md) и [историю изменений](../CHANGELOG.md).
