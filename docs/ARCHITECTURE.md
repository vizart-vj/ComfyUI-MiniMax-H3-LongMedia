# 0.4.2 Architecture

## Unified clip engine

LongMedia 0.4.2 uses one sequential generation executor for both long-form timeline policies:

- `fixed` — generated by `segmented_continuation` from `segment_duration`;
- `planned` — generated by `multiclip` from Planner clip durations.

The shared executor owns per-clip conditioning, global/local timeline conversion, Motion Context, source-audio slicing, lip-sync timing, handoff and sampling. Output assembly is workflow-specific.

## Workflow mode vs timeline policy

`workflow_mode` controls H3 conditioning semantics (`hybrid_auto`, `ref2va_full`, `video_ref_edit`, etc.). The long-form policies select clip boundaries. A connected Planner is used only by `workflow_mode=multiclip`.

## LongMediaPlan

`LongMediaPlan` is the immutable runtime contract between Setup, Sampler and Decode. It stores geometry and lightweight per-pass state, but intentionally does not retain CLIP/text-encoder/model patcher objects after Setup.

## Memory architecture

The sampler can combine:

- Dynamic VRAM model streaming;
- adaptive MLP token chunking;
- bounded streamed QKV;
- compressed INT8 K/V storage for long Sol attention;
- chunked output projection;
- final-output streaming;
- inter-block and denoise-step memory guards;
- geometry-aware attention preflight.

The goal is preventive memory routing with stock-math fallback where an optimized kernel does not pass parity checks.

## MultiClip native continuous VideoVAE decode

MultiClip clips are generation units, not VideoVAE decode units. The first clip owns the native H3 startup prefix. Every following continuation removes only the repeated native 5-frame / 2-video-latent-token prefix before its video latent is appended. The assembled timeline is validated on the native `T = 5*k + 2` H3 video-latent grid and decoded once with the H3 VideoVAE.

This replaces the discarded per-clip decode + RGB seam-repair experiments and keeps the VideoVAE temporal state continuous across the full MultiClip output. Generated audio remains handled on its own timeline because the H3 audio latent rate differs from the video latent rate.

## Workflow ownership

Segmentation controls and latent continuation stitching belong only to `manual` and `segmented_continuation`. MultiClip may contain multiple sequential sampling passes, but it is not segmentation and must not inherit segmentation overlap/stitch semantics.

## Modulation-row compatibility

The low-VRAM chunked transformer path accepts both scalar and multi-element MiniMax modulation-row layouts. Row-wise modulation is applied without coercing a multi-element tensor to a Python scalar, including the final video/audio output heads.
